Fitting Room Queue

Two views of the store fitting-room experience. The Customer view is open and lets a shopper track or cancel their own F11 ticket. The Staff view is the store associates' operations board - picking requests, fitting-room availability, operations KPIs and the full F11 queue lifecycle - whose write actions are role-gated and send a staff token.

Track your fitting-room ticket

Enter the ticket id you were given (tkt-...) to see its live status, assigned fitting room and items. You can cancel your own ticket at any time - no staff sign-in needed.

Request a fitting-room place

Simulate requesting a place in the queue so this demo is self-contained. Enter the SKUs you want to try on (comma-separated), then request a ticket.

This uses the open POST /api/queue endpoint. No token required.

Create a demo picking request

Simulate a customer staff-assist request (F10) so you have a task to work.

Submitting a request is open (F10). The role-gated actions on each task card (accept / reject / prepare) use the staff token above.

Manage a fitting-room queue ticket (F11 lifecycle)

Enter a ticket id, then confirm the place and advance it through the lifecycle, notify readiness, record completion, or record an exception.

Fitting-room queue lifecycle managed via the F11 state machine. Customer actions are open; staff confirm / advance actions are role-gated. Runs fully offline with deterministic mocks.
